# Caption

Most company pilots of AI agents never make it into daily use. That's the message from nearly every write-up I read this month. The reasons they give are rarely about the technology. They're scope that keeps growing, messy data, and nobody deciding who checks the output.

I don't run a company pilot. I run a one-person setup: three agents (research, content, scheduling) and a dashboard I built in a single session. It's small and it's pre-revenue. But it's real, and I've been using it since. So I went back through it and asked which choices kept it from stalling. Three stood out.

**Each agent got one job.**

The temptation was to build one clever assistant that does everything. I did the opposite. The researcher only researches. The content agent only drafts. The scheduler only handles timing. They can't wander into each other's work, which also means that when something goes wrong, I know where to look.

**The data came first.**

Before any agent touched my reference material, I spent time sorting it. 83 files, each classified so an agent can find the right one instead of guessing. It was the least exciting part of the whole build. It's also the part I'd skip next time if I were rushing, and I'd regret it, because an agent working from a pile of unsorted files gives you confident nonsense.

**Nothing moves without me.**

Every handoff has a defined shape, and every piece of content sits in a queue until I approve it. This is the governance piece, and mine is tiny: one person, one approval button. Still, it changes the question from "can I trust the agent?" to "did I look at this?" The second one I can answer.

What I can't tell you is whether this holds up at scale. A team of forty with real budgets and conflicting priorities is a different problem, and one session of building doesn't prove anything about it. I also can't give you a clean failure rate for pilots, because the numbers I found disagree with each other. "Most stall" is as far as I'll go.

But the pattern matches what I saw at my own desk. The agents that would have failed were the ones I'd have made too broad, fed with a mess, and left unchecked. Narrow, fed properly, reviewed: that's it. Nothing clever.

If you're about to start an agent project at work, try this first. Write down the one job. Then write down who approves the output. If you can't answer either in a sentence, the pilot is already in trouble.

Cheers!
